## Request flow

1. A client calls `ActionRequest:InvokeServer(action, ...)` (wrapped by `client/Net.request`).
2. `server/Services/Net` checks the action is registered, applies a per-player global limit
   (25 burst, 12/s) and the action's own limit, and requires the player's data to be loaded.
3. The handler validates every argument (`Core/Validate`, `Wallet.isValidAmount`, config
   lookups) and calls pure Core logic that mutates the profile without yielding.
4. On success the profile is marked dirty and a fresh snapshot is queued for that client.

The client never sends amounts, results, outcomes or ownership. It sends ids and intentions.

## Player data (DataStore `MutateTheWorld_Players_v1`, key `player_<UserId>`)

Stored as `{ data = <profile>, lock = { jobId, time }, saveCount }`. Profile (version 2):

| Field | Meaning |
| --- | --- |
| currencies | coins, dna, ice, toxic, plasma, cosmic (non-negative integers, capped at 1e15) |
| pendingCoins | coins waiting in the island collector (capped by collector level) |
| creatures | map id -> { id, species, mutation, level, slot?, seed, acquiredAt, protectedUntil, starter, source } |
| upgrades | levels: pads, collector, chamber, island, security, storage |
| biomes | unlocked biome ids |
| discovered | species, recipes (incl. evolutions), combos ("species:mutation") |
| stats | totalEarned, mutations, evolutions, captures, steals, stolenFrom, defended, failedHeists, trades |
| xp | player XP (level derived) |
| tutorial | step, done, skipped, rewarded, everDone (sticky, for raid protection), dna/ice pickup counters |
| daily / claimed | daily streak, claimed research + collection milestones |
| settings | sfx, popups, reducedEffects, uiScale (0.7–1.6) |
| activeMutation | in-progress chamber job (survives disconnects) |
| heist | protectedUntil (post-theft protection), shieldCooldownUntil |
| cosmetics | owned themes/auras, equipped theme/aura |
| purchases | processed developer-product PurchaseIds (last 100) |
| passBonuses | recomputed every session from verified game pass ownership |
| flags | starterGiven |

`DataSchema.load` migrates old versions, fills missing fields, clamps numbers, removes
invalid creatures/slots and refunds an orphaned mutation job.

## Session safety

- Load takes a session lock with `UpdateAsync`. A live lock held by another server makes this
  server wait and retry (6 x 5 s) and then kick with a "rejoin in a minute" message. Locks older
  than 10 minutes are treated as abandoned.
- Save uses `UpdateAsync` and refuses to write if another server owns the lock, so a stale
  server can never overwrite newer data. Saves for a player are serialized.
- Saves: autosave every 90 s (dirty only), on leave (and release lock), on `BindToClose`, and
  immediately after trades, heists and purchases. Retries use exponential backoff and respect
  the DataStore request budget.
- If DataStores are unavailable (unpublished place, Studio API access off) the server switches
  to session-only memory storage and tells players.
